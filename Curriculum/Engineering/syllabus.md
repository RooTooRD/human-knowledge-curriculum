# Engineering Syllabus

| Unit | Prerequisites | Ordered lessons | Observable outcomes | Common misconception | Mastery checks |
|---|---|---|---|---|---|
| `ENG-B01` Problem framing, requirements, constraints, trade-offs, design cycle | `FND-B10`, `MAT-B05` | 1. Need/stakeholder; 2. requirement/specification; 3. constraints/criteria; 4. concepts/trade studies; 5. iterate/verify | Write testable requirements; generate alternatives; select transparently | The first proposed solution is not the problem definition | ☐ Produce design brief; ☐ defend trade matrix |
| `ENG-B02` Sketching, models, prototypes, measurement, tolerances, documentation | `ENG-B01`, `PHY-B01`, `WRT-B05` | 1. Sketch/projection; 2. diagram/model; 3. prototype types; 4. measurement/tolerance/fit; 5. drawing/BOM/test record | Communicate design; build purpose-fit prototype; specify tolerances | Greater precision increases cost and is not always useful | ☐ Fabricate from peer drawing; ☐ pass dimensional inspection |
| `ENG-I01` Mechanics of materials, structures, statics, dynamics, failure | `ENG-B02`, `PHY-I01`, `MAT-I06` | 1. Loads/equilibrium; 2. stress/strain; 3. beams/frames; 4. vibration/buckling; 5. fracture/fatigue | Calculate structural response; select geometry/material; predict failure | Strong material alone does not make a safe structure | ☐ Analyze/design structure; ☐ test failure prediction |
| `ENG-I02` Reliability, safety factors, hazards, risk, standards, ethics | `ENG-B01`, `SYS-I05`, `PHI-I05` | 1. Failure probability/reliability; 2. factors/margins; 3. FMEA/fault tree; 4. codes/standards; 5. professional duty | Quantify reliability; conduct hazard analysis; make ethical safety decisions | Meeting minimum code does not exhaust professional responsibility | ☐ Complete safety case; ☐ defend risk acceptance |
| `ENG-I03` Circuits, electronics, signals, power, conversion | `ENG-B02`, `PHY-I02` | 1. Circuit laws; 2. diodes/transistors/op-amps; 3. analog/digital signals; 4. filters/conversion; 5. power systems | Design/analyze circuits; measure signals; calculate power/efficiency | Ground is a reference, not a magical sink | ☐ Build/debug circuit; ☐ pass specification tests |
| `ENG-I04` Sensors, actuators, embedded computation, feedback, control | `ENG-I03`, `CSC-I05`, `SYS-I03` | 1. Sensor physics/calibration; 2. actuator/driver; 3. microcontroller/real time; 4. interfaces/protocols; 5. feedback integration | Build embedded control loop; calibrate; meet timing/safety | Sampling and actuator limits cannot be ignored in software | ☐ Deliver closed-loop prototype; ☐ test disturbances/failures |
| `ENG-I05` Thermofluids | `PHY-I04`, `MAT-I07` | 1. Properties/control volumes; 2. energy/entropy; 3. conduction/convection/radiation; 4. fluid statics/dynamics; 5. turbines/pumps/refrigeration | Balance mass/energy; size heat/fluid components; evaluate cycles | Bernoulli equation does not apply without assumptions | ☐ Design thermofluid system; ☐ validate calculations experimentally |
| `ENG-I06` Materials, manufacturing, metrology, quality | `ENG-I01`, `CHM-I06` | 1. Material families/properties; 2. selection; 3. forming/machining/additive/joining; 4. metrology/GD&T; 5. process capability/quality | Select material/process; specify inspection; analyze defects/capability | A prototype process may not scale economically or consistently | ☐ Create manufacturing plan; ☐ inspect and improve a batch |
| `ENG-I07` Civil infrastructure | `ENG-I01`, `ECS-B02` | 1. Structural systems; 2. geotechnics/foundations; 3. water/wastewater; 4. transport; 5. construction/asset lifecycle | Analyze infrastructure components; integrate site/environment; plan lifecycle | Infrastructure performance includes maintenance and users, not initial construction only | ☐ Design conceptual infrastructure; ☐ complete lifecycle/risk review |
| `ENG-I08` Chemical and process engineering | `ENG-I05`, `CHM-I02` | 1. Material/energy balances; 2. transport; 3. reactors; 4. separations; 5. process control/safety | Design process flows; size core units; analyze hazards | Steady state does not mean nothing flows or changes locally | ☐ Simulate process; ☐ complete HAZOP and balance |
| `ENG-I09` Biological and medical engineering | `ENG-I04`, `BIO-I03`, `HLT-I02` | 1. Biological constraints; 2. biomechanics/biomaterials; 3. biosensors/imaging; 4. devices/rehabilitation; 5. validation/regulation | Translate clinical need; design biocompatible device; plan verification | Technical performance alone does not establish clinical benefit | ☐ Build/test prototype; ☐ defend clinical/risk pathway |
| `ENG-I10` Software and systems engineering integration | `ENG-I04`, `CSC-I10`, `SYS-B01` | 1. System requirements; 2. hardware/software partition; 3. interfaces; 4. integration/test; 5. configuration/change | Architect integrated system; manage interfaces; execute staged integration | Components passing alone does not guarantee system behavior | ☐ Deliver interface-controlled system; ☐ pass integration test |
| `ENG-A01` Systems architecture, interfaces, verification, lifecycle | `ENG-I02`, `ENG-I10`, `SYS-A02` | 1. Mission/use cases; 2. functional/physical architecture; 3. interfaces/budgets; 4. verification/validation; 5. lifecycle/trade/change | Allocate requirements; manage interfaces; establish evidence of fitness | Verification asks built-right; validation asks right thing | ☐ Produce architecture baseline; ☐ trace requirements to tests |
| `ENG-A02` Human factors, usability, accessibility, sociotechnical design | `ENG-A01`, `CSC-I11`, `SOC-I03` | 1. Human capabilities/error; 2. task/work analysis; 3. interface/team design; 4. accessibility; 5. organizational context | Redesign around actual work; test diverse users; reduce predictable error | Labeling an event “human error” often stops analysis too early | ☐ Complete human-factors study; ☐ demonstrate safer redesign |
| `ENG-A03` Sustainable design, lifecycle, circularity, resilience | `ENG-I02`, `ECS-I08`, `ECO-I03` | 1. Functional unit/boundary; 2. lifecycle inventory/impact; 3. durability/repair/reuse; 4. material/energy circularity; 5. climate resilience | Compare lifecycle alternatives; design repair/recovery; avoid burden shifting | Recyclable does not mean recycled or low impact | ☐ Complete lifecycle assessment; ☐ redesign for resilience/circularity |
| `ENG-A04` Project leadership, cost, schedule, procurement, regulation | `ENG-A01`, `BUS-I06`, `LAW-I06` | 1. Work breakdown/estimate; 2. schedule/resources; 3. cost/earned value; 4. contract/procurement; 5. permits/stakeholders/risk | Plan/control project; select procurement; manage regulated change | Schedule compression often increases cost/risk rather than creating free time | ☐ Deliver executable project plan; ☐ respond to change scenario |
| `ENG-A05` Integrated design-build-test capstone | `ENG-A01`, `ENG-A02`, `ENG-A03`, `ENG-A04` | 1. Need/research; 2. requirements/concepts; 3. detailed design; 4. build/integrate; 5. verify, validate, document, handoff | Deliver functioning responsible system; manage evidence/iteration/team; communicate trade-offs | A successful demonstration is not full verification across requirements | ☐ Pass design reviews and acceptance tests; ☐ deliver reproducible handoff |
| `ENG-E01` Frontier engineering research and responsible innovation | `ENG-A05`, `RSH-E01` | 1. Frontier need/state of art; 2. scientific/engineering hypothesis; 3. prototype/model; 4. rigorous benchmark; 5. scale, ethics, transfer | Produce original engineering contribution; validate against baseline; assess deployment implications | Novel prototypes are not innovations until feasibility and value are demonstrated | ☐ Produce peer-reviewed artifact; ☐ pass technical/responsibility defense |
