# Artificial Intelligence Syllabus

| Unit | Prerequisites | Ordered lessons | Observable outcomes | Common misconception | Mastery checks |
|---|---|---|---|---|---|
| `AIX-B01` AI concepts, history, task types, capabilities, and limitations | `FND-I03`, `CSC-B01` | 1. Intelligence and automation; 2. symbolic/statistical history; 3. prediction, generation, planning, perception; 4. training/inference; 5. benchmarks, limits, hype | Classify AI systems; explain data/model/objective; evaluate a capability claim | AI is neither magic agency nor merely a conventional database | ☐ Analyze five deployed systems; ☐ separate demonstrated, inferred, and claimed capability |
| `AIX-B02` Everyday AI use, prompting, verification, privacy, and oversight | `AIX-B01`, `COM-I06` | 1. Task suitability and risk; 2. context, instruction, examples, output format; 3. iteration and tool use; 4. source verification; 5. sensitive data, disclosure, human accountability | Prompt effectively; verify outputs; decide when not to use AI | Fluent output is not evidence of truth or comprehension | ☐ Complete a verified AI-assisted task; ☐ document human checks and rejected output |
| `AIX-I01` Agents, search, constraints, planning, and games | `AIX-B01`, `CSC-I02` | 1. State/action/goal; 2. uninformed/heuristic search; 3. constraint satisfaction; 4. planning; 5. adversarial search and uncertainty | Formalize problems; implement search/planning; evaluate heuristics | A faster heuristic can sacrifice completeness or optimality | ☐ Solve one CSP/planning task; ☐ prove/measure algorithm properties |
| `AIX-I02` Knowledge representation, reasoning, uncertainty, and probabilistic models | `LOG-I03`, `STA-I01`, `CSC-I01` | 1. Logic/rules/ontologies; 2. inference and defaults; 3. graphical models; 4. probabilistic inference; 5. knowledge graphs and hybrid reasoning | Encode knowledge; perform logical/probabilistic inference; state closed/open-world assumptions | Representations always select and omit features of the world | ☐ Build/query a knowledge model; ☐ compare symbolic/probabilistic treatment |
| `AIX-I03` ML problem formulation and supervised/unsupervised learning | `STA-I04`, `CSC-I03` | 1. Task, target, data, loss; 2. features/labels/splits; 3. classification/regression; 4. clustering/latent structure; 5. baseline, evaluation, deployment shift | Frame ML tasks; prevent leakage; select metrics and baselines | More data cannot fix a target that encodes the wrong objective | ☐ Produce model card/problem formulation; ☐ build leakage-free baseline |
| `AIX-I04` Features, trees, ensembles, kernels, clustering, reduction | `AIX-I03`, `MAT-I06` | 1. preprocessing/feature design; 2. trees and ensembles; 3. distance/kernels; 4. clustering; 5. PCA/manifold orientation | Implement/compare classical methods; explain decision behavior; validate clusters | Cluster labels are not discovered natural kinds without external warrant | ☐ Benchmark methods; ☐ interpret errors and feature influence |
| `AIX-I05` Neural networks, backpropagation, optimization, representation | `AIX-I03`, `MAT-A05` | 1. Neuron/layer/activation; 2. computation graph/backprop; 3. loss/gradient/optimizer; 4. regularization/normalization; 5. representation and diagnostics | Derive backprop; train/debug a network; reason about capacity/generalization | Deep networks do not automatically learn causal or human-like concepts | ☐ Implement backprop/training; ☐ diagnose overfit/optimization failure |
| `AIX-A01` Deep learning for language, vision, audio, and multimodal data | `AIX-I05`, `CSC-I02` | 1. Convolution and spatial models; 2. sequences/attention; 3. audio/time-frequency; 4. embeddings/contrastive learning; 5. multimodal alignment/evaluation | Build domain models; choose architecture; evaluate robustness across slices | High benchmark score may rely on spurious dataset cues | ☐ Train one domain model; ☐ conduct shift/error audit |
| `AIX-I06` Reinforcement learning and sequential decisions | `AIX-I01`, `STA-I05`, `MAT-A05` | 1. MDPs, return, policy; 2. dynamic programming; 3. Monte Carlo/TD; 4. value/policy methods; 5. exploration, offline RL, safety | Solve small MDPs; implement learning agent; evaluate reward/behavior | Reward is a proxy and maximizing it may exploit loopholes | ☐ Implement/compare RL algorithms; ☐ audit reward misspecification |
| `AIX-A02` Foundation models, transformers, tokenization, pretraining, scaling | `AIX-A01`, `LIN-B03` | 1. Tokens/embeddings; 2. self-attention/transformer; 3. objectives and corpora; 4. scaling, compute, data; 5. adaptation and emergent behavior claims | Trace transformer computation; explain pretraining; evaluate scaling evidence | Next-token prediction can yield broad behavior without guaranteeing grounded truth | ☐ Implement a small transformer; ☐ analyze a scaling/capability claim |
| `AIX-A03` LLM inference, prompting, retrieval, tools, agents, tuning, evaluation | `AIX-A02`, `CSC-A02` | 1. Decoding/context; 2. structured prompting; 3. embeddings/RAG; 4. tools/workflows/agents; 5. fine-tuning and evaluation | Build grounded LLM system; choose adaptation; evaluate end-to-end tasks | Retrieval reduces but does not eliminate hallucination | ☐ Deliver cited RAG/tool system; ☐ benchmark quality, latency, cost, failure |
| `AIX-A04` Generative failure, interpretability, robustness, and security | `AIX-A02`, `SEC-A01`, `STA-A06` | 1. Hallucination/calibration; 2. distribution shift/adversarial inputs; 3. prompt injection/data poisoning/exfiltration; 4. interpretability methods; 5. red-team and layered mitigation | Threat-model generative systems; measure failures; validate mitigations | System prompts alone are not a security boundary | ☐ Run adversarial evaluation; ☐ demonstrate defense and residual risk |
| `AIX-A05` Fairness, accountability, labor, copyright, safety, governance | `AIX-I03`, `PHI-I05`, `LAW-I06`, `ECO-I03` | 1. Stakeholders/impact; 2. fairness and discrimination; 3. transparency/accountability; 4. labor, authorship, copyright, concentration; 5. safety standards/regulation | Conduct impact assessment; compare governance tools; assign accountability | Technical fairness metrics cannot settle political/legal legitimacy | ☐ Produce governance dossier; ☐ defend deployment/nondeployment decision |
| `AIX-A06` Robotics, perception, control, and embodied intelligence | `AIX-A01`, `ENG-I04`, `SYS-I03` | 1. Robot frames/kinematics; 2. sensing/localization; 3. mapping/planning; 4. feedback/control/learning; 5. human-robot safety | Integrate perception-plan-control loop; quantify physical uncertainty; fail safely | Embodiment adds latency, wear, contact, and safety absent from pure simulation | ☐ Build a robot simulation/prototype; ☐ pass disturbance/safety tests |
| `AIX-E01` AI research methods and frontier architectures | `AIX-A01`, `AIX-A03`, `RSH-E01` | 1. Frontier literature/problem; 2. baselines/ablations; 3. architecture/training innovation; 4. compute/data evaluation; 5. reproducibility and dissemination | Design rigorous AI research; isolate causal contribution; release auditable artifacts | More compute and benchmark wins do not alone establish scientific insight | ☐ Produce original artifact/paper; ☐ pass ablation and replication review |
| `AIX-E02` Advanced AI safety, alignment, evaluation, and institutions | `AIX-A04`, `AIX-A05`, `SYS-A04` | 1. Objective/oversight problems; 2. scalable evaluation and monitoring; 3. misuse/systemic/catastrophic risk; 4. assurance and defense-in-depth; 5. institutions, coordination, foresight | Build threat/evaluation models; compare safety proposals; design adaptive governance | Uncertain extreme risk is neither proof of doom nor reason for dismissal | ☐ Complete adversarial safety case; ☐ defend institutional design under scenarios |
