# Phase 4 Project and Assessment Schema

## Design principle

Assessment begins with the observable outcomes already declared in `syllabus.md`.
The evidence task must elicit the same intellectual operation: a learner asked to
derive, analyze, design, perform, or defend must actually do that operation.

## Project record

```markdown
## `DOMAIN.PRJ.S` — Small project title

| Field | Specification |
|---|---|
| Scale | Small · 2–8 hours |
| Prerequisites | Unit IDs |
| Purpose | Transfer claim tested |
| Brief | Authentic problem or question |
| Deliverables | Inspectable artifacts |
| Milestones | Proposal, draft, test, revision, defense as appropriate |
| Constraints | Tools, sources, time, safety, audience, format |
| Evidence | What establishes authorship and mastery |
| Safety and ethics | Required review or “not applicable,” with justification |
| Extension | Optional harder variant |
```

Project IDs end in `.S`, `.M`, `.L`, and `.C` for small, medium, large, and capstone.

## Project contribution matrix

```markdown
| Unit | Primary project | Contribution | Required artifact |
```

Every graph unit appears exactly once. The primary mapping prevents invisible coverage;
a unit may also support later integrative projects.

## Unit assessment record

The compact matrix form is canonical:

```markdown
| Unit | Formative check | Summative task | Mode | Conditions | Pass evidence | Reassessment |
```

The summative task must explicitly reproduce every semicolon-separated observable
outcome from the syllabus. Conditions state whether work is timed, open-resource,
collaborative, computational, performed, or orally defended.

## Criterion-referenced rubric

| Criterion | Weight | Minimum evidence |
|---|---:|---|
| Accuracy and reasoning | 40% | Correct claims, computations, interpretations, or decisions |
| Method and evidence | 25% | Appropriate method, traceable sources/data, justified assumptions |
| Artifact or performance quality | 20% | Functional, complete, usable, or technically controlled result |
| Communication and reflection | 15% | Clear explanation, limitations, response to criticism, revision |

Default mastery requires **75/100**, no criterion below **60%**, and passage of every
non-compensable safety, ethics, attribution, and validity check. A discipline may raise
the threshold or add a specialist criterion.

## Assessment-mode vocabulary

`written exam`, `oral exam`, `essay`, `proof`, `problem set`, `programming assignment`,
`laboratory`, `fieldwork`, `case analysis`, `simulation`, `performance`, `portfolio`,
`presentation`, `design review`, and `research`.

## Evidence integrity

- Cite sources, data, code, collaborators, and AI assistance.
- Preserve drafts, lab notes, commits, calculations, or rehearsal records as applicable.
- Use oral questioning or a live modification when independent authorship is uncertain.
- Never infer mastery from attendance, time spent, confidence, or polish alone.
- Do not use an inaccessible presentation format to measure a construct unrelated to
  that format; provide an equivalent route that preserves the target skill.
